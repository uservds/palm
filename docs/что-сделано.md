## Известные ограничения — страница /возможности/совместимость-пар (Обновлено: 2026-10-23 → 2026-10-24)

- [ ] **Нет валидации/разметки руки при загрузке фото.** Сейчас пользователь может 
      загрузить любые две фотографии (в том числе обе левые руки, или два фото 
      одной и той же руки) — система не проверяет и не помечает, какая рука 
      загружена (левая/правая), и не требует конкретно активную (доминантную) 
      руку, хотя для хиромантии это принципиально.
      
      Уточнение (24.10.2026, после проверки у открытых источников по 
      хиромантии): активная рука — не обязательно правая. Это рука, которой 
      человек пишет: у правшей — правая, у левшей — левая. Активная рука 
      показывает текущую жизнь и сознательные выборы, пассивная — врождённые 
      склонности и наследственность. Поэтому систему нельзя жёстко привязывать 
      к «правой руке как правильной» — нужно либо спрашивать пользователя, 
      левша он или правша, либо не требовать конкретную сторону вовсе.
      
      Требуется на этапе Приоритета 10 (MediaPipe): 
      1) автоматическое определение левой/правой руки по 21 точке, 
      2) явная подсказка/маркировка в UI какая рука сейчас в слоте, 
      3) короткий вопрос пользователю («вы левша или правша?») при первом 
         скане, чтобы определить, какая рука у него активная, 
      4) валидация — предупреждение, если пользователь явно загрузил 
         обе одинаковые руки (например, обе левые), или не ту руку, которая 
         указана как активная для него.
      До подключения MediaPipe — прототип принимает любое фото без проверки, 
      это ожидаемое поведение на уровне UI-заглушки.

### Инфраструктурные уроки (важно для дальнейшей работы)

11. **Prisma 7 обязательно требует driver adapter.** Rust-движок убран
    полностью — вне зависимости от генератора (`prisma-client` или
    legacy `prisma-client-js`), `PrismaClient` не инициализируется без
    явного адаптера. Решение: `@prisma/adapter-pg` + `pg`, адаптер
    передаётся в конструктор (`new PrismaClient({ adapter })`,
    `backend/src/lib/prisma.js`). Генератор в итоге оставлен
    `prisma-client-js` (deprecated, но стабильный, выдаёт обычный
    скомпилированный `.js`) — новый `prisma-client` выдаёт только
    TypeScript-исходники без компиляции, что несовместимо с проектом без
    TS-тулчейна.
12. **Перенос Replit → ПК выявил разрыв между документацией и кодом**:
    `replit.md` на момент проверки утверждал, что frontend — React/Vite и
    Next.js-переход «не выполнен», хотя по факту `frontend/` уже был
    полноценным Next.js 16 App Router (подтверждено по `package.json`).
    Документацию синхронизировать отдельно.
13. **Облачная БД для разработки на ПК**: первая попытка (бесплатная
    Prisma Postgres через `npx create-db`) не заработала стабильно
    (`P1017: Server has closed the connection`, повторялось после
    исключения антивируса/VPN как причины). Вторая попытка — Neon,
    упёрлась в то, что connection string по умолчанию давался через
    PgBouncer-пуллер (хост с суффиксом `-pooler`), который не поддерживает
    DDL-команды `prisma migrate dev`. В итоге для разработки на ПК выбран
    **локальный PostgreSQL** (через `winget install --id
    PostgreSQL.PostgreSQL.16`) — самый предсказуемый вариант без сетевых
    сюрпризов. Для облачной версии (Replit) используется отдельная БД
    (через Secrets), с собственным `DATABASE_URL`.
14. **Передача пакетов правок текстом в чате ненадёжна** — при большом
    количестве файлов часть терялась при копировании (пример: весь
    Auth-блок из backend, кроме Prisma-схемы, не был перенесён с первой
    попытки). С этого этапа правки на несколько файлов передаются
    **архивом (zip)** с инструкцией, распаковка — через `Expand-Archive
    -Force` (мёрджит файлы, не стирает остальное), не через «Извлечь всё»
    в проводнике (однажды стёр часть проекта).
15. Replit-лимиты исчерпаны на оставшуюся часть месяца (27.10.2026) —
    код полностью синхронизирован через GitHub (`uservds/palm`, ветка
    `main`), финальный перезапуск backend и проверка Auth в облачной
    версии отложены до возобновления лимитов.
